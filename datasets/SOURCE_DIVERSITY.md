# Source Diversity Accounting

## Purpose

Prevent source volume or accessibility from substituting for Haitian Creole representativeness.

## Status

Current status: SUBMITTED_TO_REVIEW

Authorization effect: NONE

Machine-readable ledger: `configs/governance/source_diversity.yaml`

## Accounting Dimensions

The ledger records candidate domain, register, content origin, modality, temporal period, and Haiti/diaspora geography. Values are evidence-backed metadata claims, not measured corpus proportions. `UNKNOWN` is preserved when evidence is insufficient.

Large encyclopedia, Bible, web-crawl, or translated resources must not dominate a release merely because they are easy to acquire. A future release must report distributions and gaps across government/civic, education, health, disaster, news, reference, religion, culture/history, informal/conversational, and diaspora content.

## Scientific Safeguards

- Do not infer author demographics, geography, dialect, or community identity from linguistic stereotypes.
- Keep historical and contemporary periods separate.
- Keep native, translated, ASR-derived, OCR-derived, normalized, synthetic, mixed, and unknown origins separate.
- Treat family-level diversity as discovery evidence only.
- Report missing coverage rather than manufacturing balance from weak sources.

## Acceptance Criteria

- Every non-synthetic source has one accounting record.
- Unknown values remain explicit.
- Diversity metadata never grants collection or release authorization.
- Release composition requires example-level provenance and measured distributions.
