# Annotation

## Purpose

`annotation/` contains annotation guidelines, examples, and tool templates.

## Status

Current status: SUBMITTED_TO_REVIEW

Owner: Codex

Requires expert validation: Yes before any real annotation campaign.

## Current State

The repository includes general annotation guidelines, task examples, Label Studio templates, and Doccano templates. These are scaffold materials and should not be treated as final campaign instructions.

## Requirements

- Preserve raw Kreyol spelling unless the task is normalization.
- Mark uncertainty rather than guessing.
- Use gold examples and double annotation for quality control.
- Adjudicate disagreements and report agreement.
- Keep annotator identities and audit logs private.
- Do not collect sensitive personal information unless necessary and approved.

## Dependencies

- `annotation/guidelines.md`
- `annotation/QUALITY_CONTROL.md`
- `annotation/ADJUDICATION_PROTOCOL.md`
- `DATA_ACCESS_POLICY.md`

## Acceptance Criteria

- Every annotation task has guidelines, examples, uncertainty policy, and adjudication process.
- Label schemas are expert-reviewed before large-scale annotation.
